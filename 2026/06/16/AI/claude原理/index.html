一、核心认知：Agent 的本质公式

在深入源码之前，首先需要建立一个本质认知：

Agent 不是一个神秘的概念， Agent = CLI + REPL + 大模型 + 记忆

组件 作用 Claude Code 对应
CLI 用户交互入口，不仅仅是CLI，图形化界面的都算 main.tsx 引导的命令行界面
REPL 核心执行循环 QueryEngine 的 Read-Eval-Print Loop
大模型 决策大脑 Claude API
记忆 状态与上下文 context.ts + AppStateStore

这个公式可以解释所有 AI Agent 系统：

  • Claude Code：编程 Agent
  • Cursor Composer：编辑器内 Agent
  • AutoGPT：通用 Agent
  • Perplexity：搜索工具（缺少 REPL 和记忆）

九、核心机制深度解析

1. REPL：从传统到 AI 驱动

传统 REPL QueryEngine REPL
Read 读取用户输入 读取用户输入 + 上下文 + 历史
Eval 直接执行用户输入的代码 调用 LLM，让 LLM 决定下一步做什么
Print 代码执行结果 文本 + 工具调用 + 用户询问
Loop 继续循环 继续循环，直到任务完成

2. Slash Command vs Tool

维度 Slash Command Tool
调用者 用户手动输入 /command AI 模型自动决策
触发方式 显式、确定性 隐式、智能判断
本质 提示词模板注入 函数调用协议
设计目标 快捷操作、模板化指令 赋予 AI 行动能力
Token 成本 极低 较高（工具定义每次发送给 LLM）

  • ** Slash Command 是什么：以斜杠 / 开头的特殊指令。这是一种约定俗成的设计模式，广泛存在于 IRC、Slack、Vim、Minecraft 等工具中。核心目的是用特殊前缀让程序能够立即识别**这行输入不是普通对话，而是需要特殊处理的指令。

  • Slash Command 内部可以调用 Tool：两者不是互斥的

  • 演进趋势：Slash Command 正在被 Skill 系统逐步取代（更灵活、更模块化）。

3. 上下文压缩：多层防御体系

Claude Code 不是等消息塞满后才做摘要，而是准备了六层递进的防御体系：

层级 机制 触发时机 激进程度
1 工具结果预算裁剪 工具执行前 最温和
2 snip 细粒度裁剪 工具返回后 温和
3 microcompact 微压缩 构建消息时 中等
4 context collapse 折叠视图 上下文过大时 中等
5 autocompact 自动摘要压缩 后台持续监控 较激进
6 reactive compact API 返回超限错误时 最激进
  1. 工具结果预算裁剪：执行工具之前就限制返回值大小。例如 read_file 只读取目标行附近的内容，而不是整个文件。
  2. snip 细粒度裁剪：工具返回后，删除输出中的无关行。例如 ls 输出过长时，只保留前 N 行和后 N 行，中间用 ... (50 lines omitted) ... 替换。
  3. microcompact 微压缩：识别重复模式并压缩。例如将多个连续的 {"file": "src/a.ts", "line": 1} 压缩成 {"file": "src/a.ts", "lines": [1,2,3]}。
  4. context collapse 折叠视图：将连续多轮的”工具调用-工具结果”折叠成一个摘要节点。AI 知道”做过什么”但看不到中间细节。
  5. autocompact 自动摘要压缩（占比96.8%）：后台线程持续监控 Token 用量，接近阈值时主动触发，调用 LLM 生成高质量摘要替换原始对话。
  6. reactive compact：API 返回上下文超限错误时的最后兜底手段，采用最激进的压缩策略重建消息后重试。

Q:为什么需要这么多层？

压缩是有损操作，每层压缩都会丢失信息。多层设计的目的是”尽可能用损失最小的方式解决问题”。

类比：这就像医院的”分级诊疗”——感冒去社区医院（轻度压缩），大病才去三甲医院（深度摘要）。不会一上来就做全身 CT。

Q:snip和microcompact区别

snip 是切蛋糕（丢掉中间），microcompact 是压行李（重新打包）

核心数据（基于 755 个会话的 cc-compact 工具统计）：

  • 触发压缩的会话比例：18.1%
  • 自动压缩占比：96.8%
  • 手动压缩占比：3.2%
  • 自动压缩时的上下文大小：中位数 167.3K tokens
  • 分布：95.4% 集中在 150K–175K 区间

4. 压缩 vs RAG

维度 上下文压缩 RAG
解决的核心问题 对话历史太长，窗口快满了 模型不知道某个信息
信息来源 当前会话内部 外部存储
触发时机 上下文达到阈值（~95%） 按需、由模型决策
操作本质 有损压缩：总结摘要 信息增强：检索注入
对 Token 的影响 ✅ 减少后续请求 ⚠️ 增加本次请求

形象类比：

  • 压缩 = 写读书笔记：把厚书变薄，但信息来自原书
  • RAG = 去图书馆查资料：找来新书，把相关段落贴进来

Claude Code 官方立场：放弃了基于向量检索的 RAG，转而采用 **”LLM 驱动的 Grep 循环”**。核心原因：

  1. 本地项目规模下，Grep 的工程简洁性优势明显
  2. 编程需要精确匹配，语义检索有模糊性
  3. 零维护、零延迟、无索引过期问题

5. Subagent 与 Agent Teams

特性 Subagent Agent Teams
协作模式 主代理顺序或并行调度 对等网络，直接通信
通信方式 单向汇报，成员间无交流 点对点消息、广播
上下文管理 独立窗口，返回摘要 每个成员独立实例
适用场景 结果导向的独立任务 需要讨论、相互验证的复杂任务
成本 低 高

/goal 的本质：主动开启一个循环执行的 Subagent，主 Agent 负责验收是否达到目标。这是一个 **”双模型循环”**：

  • 主模型：执行任务
  • 评估模型：验收目标是否达成

6. LSP 的本质

LSP (Language Server Protocol) = agent理解各个编程语言的接口协议

text

类比：

  • LSP 像 USB-C 接口：不管什么设备，只要遵守协议，同一个充电器就能用
  • 在 Claude 中：LSP 让 AI 能精确理解代码（跳转到定义、查找所有引用、查看调用链），而不是全文搜索

LSP vs LLM：

LSP LLM
理解对象 编程语言 自然语言
本质 通信协议 + 语言服务器 神经网络模型
输出 结构化的代码信息 人类可读的文本回复

LLM 让 AI 能和人对话，LSP 让 AI 能读懂代码。

7. MCP 的本质

MCP (Model Context Protocol) = 让 AI 连接外部数据源和工具的标准化协议。

核心价值：理论上，任何可以通过 MCP 暴露的能力，Claude Code 都能自动获得：

  • 查询数据库：mcp_postgres_query
  • 操作 Jira：mcp_jira_create_issue
  • 发送 Slack：mcp_slack_send_message

8. CLI、MCP、Skill 的统一

从 Agent 视角看，三者都实现了 Tool 协议：

维度 CLI 命令 MCP Skill

调用者 用户 AI 模型 AI 模型
实现形式 斜杠命令处理器 MCP Server，JSON-RPC 文件夹 + SKILL.md

十、关键设计哲学

1. 分层即边界

每一层都有清晰的职责边界，各司其职：

组件 职责
多头注意力 负责”谁关注谁”（建模序列关系）
FFN 负责”变成什么样”（非线性特征提取）
残差连接 负责”让梯度畅通”（解决深度问题）
层归一化 负责”稳定训练”

2. 统一抽象

CLI 命令、MCP 工具、Skill 都实现了统一的 Tool 协议：

  • 名称 + 描述 + 参数 Schema + 执行逻辑

3. 可验证性

  • 子 Agent 只返回结果摘要，避免上下文污染
  • /goal 模式中主 Agent 担任验收者，执行与评估分离

4. 接口即架构

通过严格的类型契约，所有架构约束都被编译器强制执行。开发者无法”忘记”实现某个方法。

十二、深度思考模式

核心区别：System 1 vs System 2

维度 不开启（默认模式） 开启深度思考
思考方式 直觉式、快速响应 链式推理、逐步推演
内部流程 输入 → 模型 → 输出 输入 → 思维链 → 综合 → 输出
可见性 只能看到最终回答 可以看到模型的思考过程
Token 消耗 低（1x） 高（2-4x）
响应时间 快（1-3秒） 慢（5-30秒）

十三、总结

核心洞察

Claude Code 的本质不是”AI 编程助手”，而是一个”可扩展的工程智能体平台”。

  • AI 是核心：LLM 提供决策能力
  • REPL 是骨架：提供持续的交互循环
  • Tool 是手脚：提供行动能力
  • Context 是记忆：提供环境感知
